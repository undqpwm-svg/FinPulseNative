# Приложение ФинПульс и API v1: как клиент ложится на контракт

Источник истины — контракт «ФинПульс: API приложения руководителя», v1, проект от 11.11.2026 (хранится у заказчика, в
публичный репозиторий не кладём). Здесь — как приложение его использует.

> Папка `/docs` публикуется на finpulse.smartsol.pro — документацию туда не кладём.

## Где что

| Файл | Что |
|---|---|
| `docs/js/config.js` | `apiBase` (`https://api.smartsol.pro/api/v1`; тестовый — `https://api-test.smartsol.pro/api/v1`), `appVersion`, таймаут 25 с |
| `docs/js/api/server.js` | **переходник**: запросы по контракту → DTO экранов; токены; коды ошибок |
| `docs/js/api/demo.js` | те же DTO на выдуманных данных, без сети |
| `docs/sw.js` | push по формату 9.3, открытие заявки |
| `tests/server-mock.cjs` | проверка по контракту на подменённых ответах (84 проверки) |

Экраны (`screens.js`) контракта не знают: изменится контракт — правится `server.js`.

## Эндпоинты

| Экран / действие | Контракт |
|---|---|
| запуск | `GET /version` — `min_app_version` (иначе «Обновите приложение»), `webpush_public_key`. Нет связи — вход всё равно открывается |
| вход | `POST /auth/code` → `POST /auth/token` (`challenge_id`, код); `POST /auth/refresh`; `POST /auth/logout` |
| выбор организации | `GET /orgs`: больше одной — экран выбора, одна — сразу главная; `available: false` — пометка «нет связи с 1С» |
| главная | `GET /orgs/{id}/summary` + `GET /orgs` (название) + `GET /notifications?org_id&unread_only=true&limit=1` (колокольчик) |
| счета | `GET /orgs/{id}/accounts` (суммы — `balance_kzt`) |
| календарь | `GET /orgs/{id}/calendar` (по умолчанию 28 дней), порог — `threshold` |
| заявки | `GET /orgs/{id}/requests?tab=pending|decided&limit=100&cursor` (до 5 страниц), карточка, `files/{id}` |
| решения | `POST …/approve`, `…/reject` (+ `…/return` в переходнике) с `Idempotency-Key` |
| отчёты | `reports/cash-flow`, `reports/plan-fact`, `reports/debtors?limit=5` |
| уведомления | `GET /notifications?org_id`, `POST /notifications/read` (`ids` / `all`+`org_id`) |
| профиль | `GET/PUT /me/settings`, `GET /me` |
| push | `POST /devices` (каждый запуск, если разрешено), `DELETE /devices/{id}` |

Заголовки: `X-App-Version`, `X-App-Platform: web` — на всех запросах; `Authorization: Bearer` — кроме входа и
`/version`.

## Токены

- access-токен — только в памяти; refresh-токен (одноразовый) и профиль — в `localStorage` (`finpuls-session`).
- Нет access-токена или он истекает — сначала `POST /auth/refresh`.
- `401 token_expired` → **одно** обновление на все одновременные запросы, повтор запроса.
- `401 refresh_invalid` / `unauthorized` → токены удаляются, вход, «Сессия истекла — войдите снова».
- `403 access_revoked` (при входе, обновлении или запросе) → токены удаляются, вход с текстом `message`.

## Ошибки → что видит пользователь

| Контракт | Экран |
|---|---|
| `429 resend_too_early` | «Код уже отправлен. Новый можно запросить через N секунд» |
| `429 too_many_requests` (5 кодов за час) | «На этот номер уже отправлено 5 кодов за час. Повторите через N минут» |
| `429 phone_blocked` | на входе — «Номер заблокирован после 5 неверных кодов…»; на коде — таймер блокировки, ввод закрыт |
| `400 invalid_code` | «Неверный код. Осталось попыток: N», поле очищается |
| `400 code_expired` | «Код истёк — запросите новый» + «Отправить код ещё раз» |
| `403 access_revoked` | экран входа с текстом `message` |
| `503 source_unavailable` | при входе — «Нет связи с учётом компании. Код действует ещё N мин. Повторить» (тот же код); в данных — «1С сейчас недоступна» + «Обновить»; в решении — «решение не применено» + «Повторить» |
| `504 source_timeout` | «Сервер долго не отвечает» + «Обновить»; в решении — повтор с тем же ключом |
| `409 already_decided` | карточка перечитывается: «Заявка уже согласована: кто, когда. Ваше решение не отправлено» |
| `409 not_awaiting_you` | «Нет прав на это решение» (этап сменился) + «Обновить заявку» |
| `422 action_failed` | «Учёт не принял решение» + `message`, заявка в прежнем состоянии |
| `422 comment_required` | подсветка причины отказа |
| `426 app_outdated` | «Обновите приложение» |
| `503 maintenance` | «Технические работы» |
| нет ответа | «Нет связи» + «Обновить» / «Повторить» с тем же `Idempotency-Key` |

## Что пришлось приблизить (экраны пока не меняли)

- **Дебиторка.** В v1 нет просрочки, только возраст долга. Экраны подписаны «Просрочено» и «просрочка N дней» —
  туда сейчас идёт долг **старше 60 дней** и возраст самого старого документа. Нужна правка экранов: корзины
  0–30 / 31–60 / > 60 и «возраст» вместо «просрочки».
- **Порог в сводке.** В `summary` нет `threshold`; переходник восстанавливает его как `closing + shortage` дня
  разрыва (без разрыва красных дней нет).
- **«Вернуть на доработку»** и **«Выйти со всех устройств»** — в переходнике есть, кнопок на экранах нет.
- **План-факт без плана** (`has_plan: false`, `plan: null`) — показывается как план 0.
- **Счёт поставщика** (`invoice.items`) не показывается — только файлы `files`.
- **Несколько статей** (`lines`, `budgets`) — показывается бюджет основной статьи.
- **Вкладка «Решённые»** — метка по `my_action` («Согласована» = согласовал я), не по общему `status`.
